# Прогноз офтальмологической нагрузки при диабете

Калькулятор ожидаемого числа пациентов и процедур за год для ПРЛК, интравитреальных инъекций при ДМО и витрэктомии. Популяция разделена на восемь групп: СД1/СД2 и стаж <5, 5–9, 10–19, ≥20 лет.

Используется один годовой сценарий на основе исходной матрицы СД.docx. Все 24 годовые вероятности редактируются. Исходные вероятности — экспертные предположения; опубликованные исследования задают выбранные средние и SD кратности лечения и служат научным основанием. Результат не является проверенным прогнозом для Москвы или конкретной больницы.

## Изменение исходной статистики

1. Укажите численности групп или общую численность с выбранным распределением.
2. Нажмите **«Редактировать риски»**, обновите нужные ячейки и укажите источник, дату данных и примечание. Единица таблицы — пациенты на 1000 человек в год.
3. Нажмите **«Зафиксировать значения»** и выполните расчёт. Кнопка **«Вернуть исходные риски»** восстанавливает исходную матрицу.
4. Сохраните JSON сценария для повторного использования. При загрузке JSON годового сценария восстанавливаются параметры и сведения об изменениях; таблица снова фиксируется.

Это изменения текущего браузерного сценария. Они не перезаписывают общие начальные данные приложения и не создают центральную базу статистики. Фиксация защищает от случайной правки и не является паролем или разграничением административных прав.

Модель — стратифицированная биномиальная модель пациентов с составным распределением процедур. SD кратности из исследований включён как дисперсия SD². По умолчанию дополнительная неопределённость риска отключена, CV = 0; её можно включить как отдельное допущение. Краткое описание для пользователя, таблица всех 24 начальных значений и ссылки из исходного документа находятся в [руководстве HTML](docs/model-guide.html) и [текстовой версии](docs/model-guide.txt). Численная реализация: `calculator/model.py` и `web/engine.mjs`.

## Локальный запуск

Нужен Python 3.12. Выполняйте команды из корня репозитория, при необходимости в отдельном виртуальном окружении:

```sh
python -m pip install -r requirements.txt
python -m streamlit run streamlit_app.py
```

Streamlit покажет адрес приложения. Отдельный сервер вычислений и Node.js для запуска не нужны: интерфейс, параметры, методика и численный движок собираются из файлов репозитория. Прогноз выполняется в браузерном worker; Python-реализация позволяет независимо проверять математические результаты.

## Публикация в Streamlit Community Cloud

В [Streamlit Community Cloud](https://share.streamlit.io/) создайте приложение из GitHub со следующими настройками:

| Поле | Значение |
|---|---|
| Repository | `danilalebedev/Statistic-scoring-for-diabet` |
| Branch | `main` |
| Main file path | `streamlit_app.py` |
| Python version в Advanced settings | `3.12` |

Зависимости устанавливаются из `requirements.txt`; ключи внешнего API для этого приложения не требуются. После развёртывания в **Settings → Sharing → Who can view this app** выберите **This app is public and searchable**, если ссылка должна быть доступна всем. Полученный адрес на `streamlit.app` можно передавать пользователям.

Развёртывание и настройки доступа выполняются в аккаунте владельца приложения. См. официальные инструкции Streamlit: [создание приложения](https://docs.streamlit.io/deploy/streamlit-community-cloud/deploy-your-app/deploy) и [публичный доступ](https://docs.streamlit.io/deploy/streamlit-community-cloud/share-your-app).

## Проверки

Python-проверки запускаются из корня репозитория:

```sh
python -m unittest discover -s tests -v
```

Для численных проверок браузерного движка дополнительно нужен современный Node.js:

```sh
node tests/test_engine.mjs
```

Проверки охватывают аналитические моменты, симуляцию, ввод параметров и сборку Streamlit-интерфейса. Исходники находятся в `calculator/` и `web/`, методика — в `docs/`, проверки — в `tests/`. Каталог `streamlit_component/` создаётся автоматически при запуске и не требует ручной подготовки или добавления в Git.

Уведомления о лицензиях заимствованных компонентов генерации случайных чисел сохранены в [THIRD_PARTY_NOTICES.txt](web/THIRD_PARTY_NOTICES.txt).
